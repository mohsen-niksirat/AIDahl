## ۲) ساخت ربات تلگرام

3. نام نمایشی + یوزرنیم (مثلاً `MyAIDahlAssistantBot`)

```text

byok - همان keys
manus - دستیار Manus (تصویر/ویرایش/agent)

manusqueue - وضعیت صف Manus

manusreset - پاک‌سازی قفل/صف Manus
manusdebug - عیب‌یابی Manus
prompts - پرامپت‌های آماده (مرورگر)
promptopia - همان prompts
gallery - همان prompts
```

**`/setdescription` (اختیاری):**
```text

/start · /keys · /manus · /prompts
```

## ۳) Supabase

1. پروژه جدید بساز (منطقه نزدیک کاربرانت)  
2. **Project Settings → API**  
   - `SUPABASE_URL` مثلاً `https://xxxx.supabase.co`  
   - `SUPABASE_KEY` (anon یا service_role — برای backend معمولاً service_role؛ مراقب باش لو نرود)  
3. **SQL Editor** → New query → فایل‌های SQL را **به ترتیب** Run کن: `01` تا `04`

### sql/01_user_api_keys.sql
```sql
create table if not exists public.user_api_keys (
  id bigint generated by default as identity primary key,
  user_id bigint not null,
  provider text not null,
  api_key text not null,
  base_url text,
  is_active boolean not null default true,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  unique (user_id, provider)
);

alter table public.user_api_keys enable row level security;
alter table public.user_api_keys disable row level security;

create index if not exists user_api_keys_user_id_idx
  on public.user_api_keys (user_id);
```

### sql/02_user_settings.sql
```sql
alter table public.users
  add column if not exists response_style text not null default 'html';

alter table public.users
  add column if not exists context_messages int;
```

### sql/03_phase5.sql
```sql
alter table public.users
  add column if not exists active_conversation_id uuid;

alter table public.users
  add column if not exists is_admin boolean not null default false;

alter table public.users
  add column if not exists stream_enabled boolean;

create table if not exists public.user_quotas (
  user_id bigint primary key,
  daily_limit int not null default 50000,
  used_today int not null default 0,
  reset_at date not null default current_date,
  updated_at timestamptz not null default now()
);

alter table public.user_quotas disable row level security;

create index if not exists conversations_user_updated_idx
  on public.conversations (user_id, updated_at desc);
```

### جداولی که ربات استفاده می‌کند
| جدول | نقش |
|------|-----|
| `users` | پروفایل + مدل فعال + تنظیمات |
| `conversations` | گفتگوها |
| `messages` | تاریخچه پیام‌ها |
| `usage` | مصرف توکن |
| `user_api_keys` | کلیدهای BYOK (dahl, manus, …) |
| `user_quotas` | سهمیه روزانه |

اگر جدول `users` را از قبل داری، همان کافی است؛ فقط ستون‌های alter را اجرا کن.

**RLS:** ربات با کلید backend کار می‌کند. برای سادگی مثل پروژه فعلی، RLS را روی جداول bot غیرفعال نگه داشته‌ایم (`disable row level security`). اگر anon key عمومی داری، حتماً service_role را فقط در سرور بگذار.

## ۴) کلیدهای API

### Dahl (چت مشترک / BYOK)
1. [inference.dahl.global](https://inference.dahl.global) → ثبت‌نام  
2. **fingerprint** را یک‌جا ذخیره کن (قابل بازیابی نیست)  
3. وارد شو → [Account](https://inference.dahl.global/account)  
4. از **Pool** مقداری توکن روی یک کلید **Allocate** کن  
5. کلید `dahl_…` را کپی کن → `DAHL_API_KEY`

نکته: ساخت کلید اضافی **به‌تنهایی** توکن رایگان جدید نمی‌دهد؛ ۱۰۰M هدیه **به‌ازای هر اکانت** در Pool است.

### Manus (agent / تصویر)
1. [manus.im](https://manus.im) ثبت‌نام  
2. [Settings → Developers](https://manus.im/app#settings/developers)  
3. **Create API Key** → **همان لحظه کپی** (فقط یک‌بار)  
4. تست:

```bash
curl https://api.manus.ai/v2/usage.availableCredits \
  -H "x-manus-api-key: کلید_تو"
```

باید `ok: true` و `total_credits` بیاید.

**مهم:** `locale: fa` را API قبول نکرد. در کد فعلی locale خالی است؛ فقط در صورت نیاز `MANUS_LOCALE=en` بگذار.

### سایر BYOK
کاربران از داخل ربات: **🔑 کلیدهای من → سرویس → افزودن کلید**  
- OpenRouter: openrouter.ai/keys  
- Groq: console.groq.com/keys  
- و …

1. از پوشه پروژه zip بگیر **بدون** `.env` و `.venv` (فایل‌های لازم: `main.py`, `requirements.txt`)  
2. سرویس بساز / کد را Replace کن  
3. **Environment** را مثل `.env` پر کن — حداقل:


## ۸) Manus Agent

### مفهوم
Manus **API چت OpenAI نیست**. ربات:
1. `POST https://api.manus.ai/v2/task.create` (گفتگوی جدید)  
2. یا `POST .../v2/task.sendMessage` (ادامه **همان** task — ادیت بعدی)  
3. Poll: `GET /v2/task.listMessages` + اسکن عمیق فایل‌ها  
4. دانلود فایل **با هدر** `x-manus-api-key`  
5. ارسال به تلگرام: **متن + عکس preview + فایل اصلی**  

**ساخت عکس:**
```text
/manus Generate a flat illustration of a friendly robot, pastel colors
```

**ویرایش عکس:** بعد از «اجرای تسک جدید» → عکس + کپشن

**ادامه در همان گفتگو:** پس از نتیجه، عکس/متن بعدی را بفرستید — `task.sendMessage` روی همان task.

**صف:** حداکثر `MANUS_MAX_CONCURRENT` (پیش‌فرض ۲) اجرای همزمان؛ بقیه در صف.  
**قفل گیر کرده:** `/manusreset` · **عیب‌یابی:** `/manusdebug`

**مهم:** `locale: fa` را API قبول نمی‌کند — `MANUS_LOCALE` را خالی بگذار.

### env مرتبط
```text
MANUS_API_KEY=
MANUS_DEFAULT_PROFILE=standard
MANUS_TIMEOUT_SEC=90
MANUS_POLL_INTERVAL=4
MANUS_LOCALE=
MANUS_MAX_CONCURRENT=2
MANUS_QUEUE_MAX=15
MANUS_MAX_PER_USER=1
MANUS_FOLLOWUP_TTL_SEC=7200
MANUS_STALE_LOCK_SEC=180
PROMPTOPIA_URL=https://mohsen-niksirat.github.io/promptopia/
```

### خطاهای رایج Manus
| پیام | معنی |
|------|------|
| `invalid locale` | کد قدیمی — نسخه جدید locale نمی‌فرستد |
| `cannot access local variable '_MANUS_ACTIVE'` | باگ `global` — نسخه جدید را دیپلوی کن |
| گیر روی «دریافت فایل» | `/manusdebug` + `/manusreset` |
| `unauthenticated` / 401 | کلید نامعتبر |
| `rate_limited` / 429 | ~۱۰ task/دقیقه |
| credit | سهمیه تمام |
| waiting | agent به تأیید نیاز دارد |
| عکس در سایت هست ولی در تلگرام نیست | دانلود auth یا پارسر فایل — نسخه جدید deep harvest + download with key |

## ۱۰) ظرفیت و محدودیت‌ها

### سیاست ذخیره‌سازی (مهم — جلوگیری از پر شدن Supabase)

| چیز | روی سرور ما |
|-----|-------------|
| پروفایل کاربر (`users`) | ✅ می‌ماند |
| کلیدهای BYOK | ✅ می‌ماند |
| شمارنده سهمیه (`user_quotas`) | ✅ می‌ماند |
| **گفتگوی فعلی** + آخرین ~۴۰ پیام | ✅ می‌ماند |
| گفتگوها/پیام‌های قبلی | ❌ با «چت جدید» **پاک می‌شود** |
| جدول `usage` (لاگ توکن) | ❌ پیش‌فرض نوشته نمی‌شود (`SKIP_USAGE_TABLE=true`) |
| متن چت در تلگرام کاربر | ✅ فقط در تلگرام می‌ماند (ما پاکش نمی‌کنیم) |

### سهمیه کلی هر کاربر (Lifetime)

| مقدار پیش‌فرض | env |
|---------------|-----|
| **۳٬۰۰۰٬۰۰۰** توکن مادام‌العمر | `DEFAULT_LIFETIME_TOKEN_QUOTA=3000000` |
| هشدار از **۷۵٪** | `LIFETIME_WARN_PCT=75` |
| روزانه کلید مشترک **۵۰٬۰۰۰** | `DEFAULT_DAILY_TOKEN_QUOTA=50000` |

- سهمیه **کلی** برای **همه** (کلید شخصی یا مشترک) اعمال می‌شود.  
- نزدیک سقف → پیام **⚠️ هشدار** زیر پاسخ.  
- رسیدن به سقف → **⛔️ بلاک** تا ادمین سهمیه را بالا ببرد (`user_quotas.lifetime_limit`).  
- عدد ۳M عمداً زیاد است تا کاربر عادی اذیت نشود؛ برای ربات پرمصرف می‌توانی عوض کنی.

**افزایش سهمیه یک کاربر (SQL):**
```sql
update public.user_quotas
  set lifetime_limit = 10000000
  where user_id = 123456789;
```

### محدودیت‌های پلتفرم

| لایه | محدودیت تقریبی (رایگان) |
|-----|-------------------------|
| **Deployka Nano** | **~128MB RAM**، ۱ کانتینر، CPU محدود |
| **پایتون ربات** | baseline ~30–40MB؛ فضای کم برای درخواست‌های همزمان |
| **Supabase Free** | ~500MB دیتابیس، egress محدود، connection/pooler مشترک |
| **تلگرام** | flood limit روی send/edit |
| **Dahl** | به طرح/اکانت بستگی دارد؛ کلید مشترک زود تمام می‌شود |
| **Manus** | **~10 task.create / دقیقه** به‌ازای هر user** + credits |

### ربات چگونه رفتار می‌کند
- `pyTelegramBotAPI` معمولاً پیام‌ها را threaded پردازش می‌کند  
- هر پیام چت: چندین HTTP به Supabase + یک فراخوانی مدل (تا ~۹۰s)  
- هر Manus: poll تا `MANUS_TIMEOUT_SEC` (پیش‌فرض ۹۰s) → **thread/RAM** اشغال می‌شود  
- استریم: هر ~۱.۲s ویرایش پیام تلگرام  

### تخمین «چند نفر همزمان بدون شات‌داون؟»

> این اعداد **تجربی/مهندسی** هستند نه SLA رسمی Deployka. باید با تست واقعی تنظیم شوند.

| سناریو | تعداد تقریبی همزمان | ریسک |
|--------|---------------------|------|
| چت متنی کوتاه، بدون Manus | **۵–۱۰** همزمان | پایین — حالت امن |
| اسپایک لحظه‌ای | **۱۵–۲۵** | متوسط — اگر استریم+تاریخچه سنگین باشد ممکن است کند/خطا |
| چت + چند Manus همزمان | **۲–۵ Manus** + چند چت ساده | بالا — سریع RAM/rate می‌گیرد |
| کاربر فعال روزانه (سبک، نه همه با هم) | **~۵۰–۱۵۰** | قابل قبول برای MVP |
| ۵۰+ چت واقعاً همزمان طولانی | **ریسک OOM / صف طولانی** | روی Nano توصیه نمی‌شود |

**جمع‌بندی عملی:**
- با **همین** Deployka Nano + Supabase Free:  
  **هدف‌گیری امن: ~۱۰ نفر همزمان** در حال چت؛  
  **حد عملی/اسپایک: ~۲۰**؛  
  **Manus سنگین: حداکثر چند تسک همزمان**.  
- برای «خیلی زیاد» کاربر همزمان باید **هاست قوی‌تر** بگیری.

### قبل از رشد چه کنیم
1. **BYOK اجباری** برای کاربران (`ALLOW_SHARED_KEY=false`) — بار از کلید تو پخش می‌شود  
2. `STREAMING_ENABLED=false` اگر زیاد شد — ویرایش پیام کمتر  
3. `HISTORY_LIMIT=10` یا `5` — payload مدل کوچک‌تر  
4. **صف Manus** (یکی‌یکی) — جلوگیری از ۱۰ thread نودثانیه‌ای  
5. ارتقای پلن Deployka / رفتن به VPS (مثلاً ۱GB RAM)  
6. مانیتور `/admin` + لاگ OOM  

### Supabase چه زمانی گلوگاه می‌شود؟
- معمولاً **بعد از RAM ربات**  
- اگر هر پیام ۸–۱۰ کوئری بزند و ۲۰ کاربر همزمان باشند، QPS بالا می‌رود ولی PostgREST معمولاً برای MVP جواب می‌دهد  
- دردسر واقعی Free: **حجم دیتابیس** (`messages`/`usage` رشد می‌کند) و **bandwidth**  
- بعداً: پاک‌سازی لاگ‌های قدیمی، ایندکس، یا پولی شدن
